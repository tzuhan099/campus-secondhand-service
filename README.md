# 校園二手物交易與預約平台

**Campus Second-hand Trading & Reservation Platform**

> **專案狀態：Design Only（僅規劃，尚未實作）**  
> 本專案為個人 AI 協作小而美系統規劃與設計作業，將產出 Requirements、RESTful API Design、OpenAPI 3.1.0、Architecture／Data Model 與 AI Collaboration 文件；本次不實作程式碼、資料庫或測試。

## 一句話價值主張

透過**商品分類及課程篩選、公開問答、簡化交易條件提案，以及直接預約／接受提案即鎖單**，協助校園使用者在同一平台尋找、確認並保留二手物品；預約成立後可利用專屬留言區協調面交細節，減少重複詢問、跨平台聯繫與多人搶單的混亂。

## 使用者、問題與主要情境

**主要使用者：** 有二手教科書、宿舍家電及日用品買賣需求的大學生、研究生；教職員與學生家長亦可使用。本系統不驗證真實校園身分。

**要解決的問題：**

1. **商品難以尋找：** 校園二手社團的貼文格式不一致，難以依商品分類、系所或課程找到需要的物品。
2. **商品資訊重複詢問：** 買家經常詢問相似的物況或配件問題，賣家必須重複回覆。
3. **交易條件不易整理：** 議價、面交時間與地點等條件分散在不同訊息中，難以確認最後約定。
4. **預約與後續聯繫不明確：** 多人表達購買意願時容易重複搶單；成功預約後也需要一個地方協調實際面交細節。

**具體情境：** 賣家刊登一台二手電風扇，填寫售價與面交地點，面交時間可選填。買家依分類找到商品並公開詢問物況；若接受賣家條件即可直接預約，若想調整價格、時間或地點，可提出正式交易條件提案。賣家接受提案時，系統直接建立預約並鎖定商品。預約成立後，雙方透過該筆預約的專屬留言區確認面交細節，最後由賣家標記交易完成。

## 系統亮點

### 1. 商品分類及條件篩選

- 分類為 `TEXTBOOK`（教科書）、`APPLIANCE`（家電）、`DAILY_GOODS`（生活用品）。
- 商品名稱、分類、物況描述與二手售價為必填；教科書的適用系所和課程名稱為選填。
- 支援依分類、商品名稱、系所及課程關鍵字篩選；預設顯示 `AVAILABLE` 商品。

### 2. 簡單的商品價格資訊

- **二手售價 `selling_price` 必填且大於 0**；購買原價 `original_price` 選填，若填寫亦須大於 0。
- 有提供原價時，系統可顯示 `selling_price / original_price × 100%`（售價占原價百分比）；未提供時顯示「原價未提供」。
- 原價由賣家自行填寫，僅供參考，系統不要求購買憑據，也不驗證實際購買金額。

### 3. 公開商品問答

- 對 `AVAILABLE` 商品，買家可以**不限次數**公開提問，賣家可針對每題回覆；如需追問，可再新增問題。
- 所有人都可查看公開問答，減少相同問題重複詢問。
- 商品進入 `RESERVED` 或 `SOLD` 後，既有問答仍可查看，但停止新增公開問答。
- 公開提問不消耗正式提案次數，也不保留商品；公開問答區不應張貼私人聯絡資訊。

### 4. 賣家設定與編輯公開交易條件

- 刊登商品時，賣家必須設定**公開售價與面交地點**；面交時間可選填。地點採文字描述，時間若填寫須為未來日期時間。
- 商品為 `AVAILABLE` 時，賣家可修改名稱、分類、物況、售價、原價、教科書資訊、面交時間及地點；`item_id` 與賣家身分不可修改。
- 若賣家修改**公開售價、面交時間或面交地點**，原有 `PENDING` 提案改為 `INVALIDATED`，原因記為 `SELLER_TERMS_CHANGED`，**每筆因此失效的提案返還該買家一次提案機會**。先前已被拒絕或買家主動撤回的提案不返還次數。
- 商品已 `RESERVED` 或 `SOLD` 時，不允許直接修改原交易條件，以免影響已成立的預約。

### 5. 每位買家最多兩次正式交易條件提案

- 每位買家針對同一商品，**同時最多一筆 `PENDING` 提案**；在有效額度內最多提交兩次正式提案。
- 提案可以調整**價格、面交時間、面交地點**的一項或多項，至少一項須與賣家目前公開條件不同；未調整的條件沿用公開設定。
- 提案價格必須大於 0；若調整價格，應低於當時公開售價。提案不提供賣家反向出價功能。
- 每次成功送出提案消耗一次機會。被拒絕或買家撤回後，可在剩餘額度內再次提案；**只有因賣家修改公開交易條件而失效的待處理提案，才返還其消耗的那一次**。
- 可用提案次數 = `2 − 已提交提案數 + 因 SELLER_TERMS_CHANGED 失效的提案數`；數值最低為 0。因其他買家預約而失效、拒絕、撤回或取消已成立預約，均不返還次數。
- 正式提案**只有提案買家及該商品賣家可以查看**，不公開給其他買家；買家可以撤回 `PENDING` 提案，賣家可以接受或拒絕。
- 提案沒有自動到期時間；待賣家處理、買家撤回、商品被預約，或賣家修改公開交易條件後才結束待處理狀態。
- **賣家接受提案即代表接受該買家的預約**，不必由買家再次按下預約按鈕。

### 6. 直接預約與接受提案即鎖單（核心亮點）

- **方式 A｜直接預約：** 買家接受商品當前的公開售價、面交地點及已提供的面交時間，即可直接預約 `AVAILABLE` 商品。
- **方式 B｜接受提案即預約：** 賣家接受 `PENDING` 提案時，系統在同一個原子性交易內將提案標記為 `ACCEPTED`、建立預約並將商品轉為 `RESERVED`，記錄最終接受的價格、時間及地點。
- **先成功鎖定者優先：** 若其他買家已成功預約，賣家不得再接受原提案；若提案先被接受且完成鎖單，其他買家也不能直接預約。衝突回傳 `409 Conflict`。
- 同一商品同一時間最多一筆有效預約。鎖定後，其餘 `PENDING` 提案改為 `INVALIDATED`（原因 `ITEM_RESERVED`），不返還已消耗的提案次數。
- `Reservation` 保存預約買家、成交價、面交地點、面交時間（可空）與來源 `DIRECT`／`OFFER_ACCEPTED`。
- **買家本人或賣家可取消有效預約**；商品恢復 `AVAILABLE`，取消紀錄仍保留，舊提案不自動恢復。由賣家確認面交完成後，商品改為 `SOLD`。
- 不設逾期自動取消或背景通知機制。

### 7. 預約成立後的專屬交易留言區

- 預約成立後，該筆預約的買賣雙方可在**專屬留言區**交換文字訊息，協調實際面交時間、地點及注意事項；留言不限次數。
- 僅該筆預約的買家與商品賣家可讀取、發送留言。公開問答與預約留言分開，預約留言不會對其他買家公開。
- 採**非即時留言**設計：不使用 WebSocket，也不提供推播通知、已讀狀態、圖片附件或其他完整聊天室功能。
- 若賣家刊登時未指定面交時間，直接預約仍可成立，預約的面交時間欄位保持空值（畫面顯示「待雙方確認」）；雙方可在留言區約定。
- 留言僅作為面交協調紀錄，**不會自動修改預約所保存的成交價格、時間、地點或預約狀態**。若雙方在留言中改約，應以雙方確認的文字內容為依據；本次不提供獨立的預約條件修改功能。
- 預約轉為 `CANCELLED` 或 `COMPLETED` 後，歷史留言保留供該筆預約雙方查看，但不能繼續發送。

## 核心使用流程（6 步驟）

1. **建立簡化使用者識別：** 使用者建立全站唯一 `nickname`，系統產生 `user_id` 與隨機操作憑證；暱稱衝突回傳 `409 Conflict`，後續操作依憑證識別身分。
2. **賣家刊登商品：** 填寫商品名稱、分類、物況、售價及面交地點；原價、面交時間、教科書系所與課程可選填，商品狀態為 `AVAILABLE`。
3. **買家搜尋與公開問答：** 依分類、系所或課程找商品，閱讀商品詳情並依需求多次公開提問。
4. **直接預約或提出條件：** 買家可直接接受賣家公開條件；也可在最多兩次的有效額度內提出價格、時間或地點調整提案。
5. **成功預約並鎖定：** 直接預約成功，或賣家接受正式提案後，商品立即轉為 `RESERVED`，其他衝突請求收到 `409 Conflict`。
6. **預約後留言與線下結案：** 買賣雙方在預約專屬留言區確認面交細節；賣家面交完成後標記 `SOLD`，任一方取消預約則恢復商品可預約狀態。

## 主要業務規則摘要

| 編號 | 規則 |
|---|---|
| BR-01 | `nickname` 全站唯一；修改商品、提案、預約或查看私人留言時，使用隨機操作憑證識別使用者。 |
| BR-02 | 商品分類為三種；教科書適用系所與課程選填。 |
| BR-03 | 二手售價必填且大於 0；購買原價選填、僅供參考。 |
| BR-04 | 公開面交地點必填、時間選填；賣家可在商品 `AVAILABLE` 時編輯。 |
| BR-05 | 買家可不限次數公開提問，賣家可逐題回覆；商品被預約或售出後停止新增公開問答。 |
| BR-06 | 每位買家對同商品最多兩次有效提案機會，同時最多一筆 `PENDING`；成功提交即消耗一次。 |
| BR-07 | 提案僅提案買家與賣家可見；買家可撤回，賣家可接受或拒絕。 |
| BR-08 | 賣家修改公開售價／面交時間／地點，使 `PENDING` 提案失效，並逐筆返還因這次修改失效的提案機會。 |
| BR-09 | 接受提案時，同一原子性交易完成建立預約與商品鎖定。 |
| BR-10 | 買家可直接按公開條件預約；同商品最多一筆有效預約，先成功鎖單者優先，衝突回傳 `409 Conflict`。 |
| BR-11 | 商品被預約後其他待處理提案失效；因其他人鎖單失效的提案不返還次數。 |
| BR-12 | 有效預約的買賣雙方可不限次數交換非即時文字留言；取消／完成後僅可查看歷史內容。 |
| BR-13 | 買家或賣家可取消有效預約，商品重新成為 `AVAILABLE`；賣家可確認完成交易，歷史資料保留。 |
| BR-14 | 賣家不得預約自己的商品或向自己的商品提案；其他人不得冒名更改商品、提案或預約。 |
| BR-15 | 提案不自動過期；本次不設帳號復原、跨裝置登入及校園身分認證。 |

## 狀態與資料一致性

- **商品 `Item.status`：** `AVAILABLE` → `RESERVED` → `SOLD`；取消預約時 `RESERVED` → `AVAILABLE`。
- **提案 `Offer.status`：** `PENDING` → `ACCEPTED`／`REJECTED`／`WITHDRAWN`／`INVALIDATED`；`INVALIDATED` 需區分 `SELLER_TERMS_CHANGED` 和 `ITEM_RESERVED`，以判斷是否返還提案次數。
- **預約 `Reservation.status`：** `ACTIVE` → `CANCELLED`／`COMPLETED`；同商品只能存在一筆 `ACTIVE` 預約。
- **鎖單一致性：** 直接預約與接受提案共用原子性鎖單邏輯，避免競爭請求產生重複有效預約。
- **提案次數：** 每位買家與商品的有效額度，按「成功提交提案數扣除因賣家改條件而失效的提案數」計算；其他已消耗次數不返還。
- **訊息可見性：** 公開問答對所有人可見；預約留言僅該筆預約買家與賣家可見。訊息儲存不等於即時聊天。
- **面交條件：** 訂單保留成立當下的約定條件；後續留言不自動改寫已保存欄位。若時間未提供，以空值表示，顯示「待雙方確認」。

## 本次不做什麼（Out of Scope）

- 不處理**線上付款、金流、物流配送與付款證明驗證**；實際付款與交付在線下完成。
- 不實作帳號密碼登入、SSO、JWT、多角色管理或真實校園身分驗證；採簡化操作憑證，不支援跨裝置登入或憑證遺失復原。
- 不做完整私人聊天室、WebSocket 即時通訊、推播通知、已讀狀態、附件與圖片上傳；僅有公開問答及**預約成立後的非即時專屬留言**。
- 不串接地圖、行事曆、付費 API、影像辨識；不要求收據或購買紀錄上傳。
- 不設多輪即時競標、提案自動到期、預約逾期自動取消、信用評分、交易評價或檢舉功能。
- 本次只交付規劃與設計文件，**不需程式碼、資料庫、可執行 API 或自動化測試**。

## 預計的主要資料實體

**公開問答與預約留言共用 `Message` 實體**，透過訊息類型與關聯區分，不另建立完整聊天系統。

| Entity | 角色與關鍵欄位（初步規劃） |
|---|---|
| `User` | `user_id`（PK）、`nickname`（唯一）、`credential_hash`。 |
| `Item` | `item_id`（PK）、`seller_id`（FK）、`category`、`name`、`description`、`selling_price`、`original_price`（可空）、`meeting_time`（可空）、`meeting_place`、`status`。 |
| `Offer` | `offer_id`（PK）、`item_id`（FK）、`buyer_id`（FK）、`proposed_price`（可空）、`proposed_meeting_time`（可空）、`proposed_meeting_place`（可空）、`status`、`invalidation_reason`（可空）。 |
| `Reservation` | `reservation_id`（PK）、`item_id`（FK）、`buyer_id`（FK）、`offer_id`（可空）、`agreed_price`、`agreed_meeting_time`（可空）、`agreed_meeting_place`、`status`、`source`。 |
| `Message` | `message_id`（PK）、`sender_id`（FK）、`item_id`（FK，可空）、`reservation_id`（FK，可空）、`reply_to_message_id`（FK，可空）、`message_type`（`PUBLIC_QUESTION`／`PUBLIC_ANSWER`／`RESERVATION_MESSAGE`）、`content`、`created_at`。公開問答關聯商品；預約留言關聯預約；公開回答以 `reply_to_message_id` 指向原問題。 |
